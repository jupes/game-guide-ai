Reviewed November 27, 2026. Scope covers the committed app and the mobile launch changes using isolated Linux containers and GitHub Actions. The release plan is in [Aetheril domain and mobile web launch](../plans/mobile-web-launch.md).

The repository supports an internal rehearsal with sample campaigns. External distribution depends on choosing and funding the HTTPS front door, verifying its access controls and application readiness, then running the real-device pilot. Keep optional live capture and paid features under their separate product decisions.

## Technical verification

- **Routing and authorization.** The isolated audit passed 182 focused checks for FastAPI and Nginx route contracts, table read/refusal behavior, Workbench authorization and response boundaries, SPA route parity, and security headers. The manifest is public and serves a neutral start address. The shareable table address names an opaque campaign. Opening it requires a current authorized account or shared-screen grant. [Home-screen installation PR #275](https://github.com/jupes/game-guide-ai/pull/275)
- **Player state and privacy.** The live two-service test exercised Chromium and WebKit with disposable PostgreSQL. It verified separate private and table slots, accepted and offered seat behavior, reconnect, Stop and End. The player projection clears during privacy-sensitive lifecycle transitions and waits for a fresh authorized picture before restoring it. [WebKit responsiveness PR #273](https://github.com/jupes/game-guide-ai/pull/273)
- **Dependencies and build.** Verified Pillow 13.0.0 and certifi 2026.11.20 in a frozen Python 3.12 environment. The isolated runtime suite passed 272 media, provider, and identity checks with FFmpeg. The exact production uv version exported hash-bearing requirements for the default and optional rerank builds. The default service-only image excluded the reranker. The narrowly scoped pyasn1 update passed 316 identity, authentication and provider checks. [Runtime dependency PR #276](https://github.com/jupes/game-guide-ai/pull/276) · [ASN.1 runtime PR #282](https://github.com/jupes/game-guide-ai/pull/282)
- **Graph and tracing.** The separate LangGraph and OpenTelemetry lockfile candidate passed 638 generation, provider, tracing, metrics and privacy checks. The production uv version exported both build profiles with hashes and the built Linux/amd64 image contained the expected patched versions. [Graph and telemetry PR #284](https://github.com/jupes/game-guide-ai/pull/284)
- **Release startup rehearsal.** Both runtime dependency candidates started with disposable PostgreSQL and advanced the schema to current. Verified readiness, both HTML entry points, manifest MIME and icons and the signed-out auth response on the exact release image, without using live credentials or traffic.
- **Session recap.** The isolated 229-check run covered bounded conversation history, retry behavior and one-document persistence against disposable PostgreSQL. The hosted pipeline passed. [Session recap PR #279](https://github.com/jupes/game-guide-ai/pull/279)
- **Performance and reliability.** The hosted UI E2E workflow has budgets for the boot and navigation paths. Headless checks establish regression coverage for those paths. Field join latency, reveal latency under the approved rollout capacity, and loss recovery on cellular are pilot measurements. [Existing UI performance gates](../../ci.md#browser-release-tracer-and-ui-performance-gate)

## UX verification

- **Entry and joining.** The phone flow begins in the Tavern or at a shared table address. A signed-out deep link reaches sign-in. Confirmed live seats expose a Join table action. An accepted seat awaiting GM confirmation may see the table-wide slot from a direct authorized address under SEC-41. Its private slot needs GM confirmation.
- **Player action priority.** Interaction decision A-33 keeps a visible locked New Campaign control with a reason. In the mobile player fixture, that filled control occupies the top of the page and can draw attention away from the lower Join table link. Check whether first-time players find Join table promptly. Follow up under 30c if the pilot confirms the issue. [Tavern interaction decisions](../../adr/gm-workbench-interactions.md)
- **At the table.** The recent WebKit fix bounds waiting for the first picture and for reveal updates. Player-specific information sits above table-wide information. The shared screen gets the table-wide slot. End clears both audiences across two live services.
- **GM Workbench.** The 242 headless UI stories at installer head 79cacf9 covered Landing, Workspace and Workbench, the Tavern, Session Control, Campaign Library, the tool rail, and reveal states. Representative stories exercise narrow, medium, wide and landscape layouts, keyboard focus and the automated accessibility gate. On the split desktop canvas and on phones, the pinned tools stay inside their rail and More remains operable. [Tool rail fix PR #272](https://github.com/jupes/game-guide-ai/pull/272)
- **Channel switching.** Hosted desktop Chromium, mobile Chromium and mobile WebKit each passed the phone regression for separate Sage and Spell conversations. The shell tests also cover a late Sage response while the phone is already in Spell. [Hosted phone regression](https://github.com/jupes/game-guide-ai/actions/runs/46073116421)
- **Assistive status updates.** Regression tests require a single announcement when an answer includes suggestions in the shared chat pane and the GM conversation. Pilot screen-reader checks still need to record the actual order and timing. [Announcement regression PR #278](https://github.com/jupes/game-guide-ai/pull/278)
- **Distribution help.** Home-screen guidance lives in an optional Tavern disclosure. People can share and use a normal browser link. Both HTML entry points use the same public app identity. A separate Chromium check parsed both manifests and reported no installability errors. The launch URL has no campaign or participant information.
- **Manual pilot evidence.** Record screen-reader announcements and order, 200% text and zoom, keyboard and touch targets, dark and light themes, phone lock and resume, slow connections, fresh sign-in from an installed app, and return to the Tavern.

## Verification boundary

The audit uses committed source, hosted test runs, synthetic campaign data and disposable database fixtures. Production hostname, network behavior, legal and commercial approvals, deployment-specific load, and real-device acceptance must be recorded against the released build. Track each release gate through the linked plan and existing Beads.

This is a pilot release assessment. Independent roadmap work still includes portrait-reuse authorization (1ir.5.5), GM control of synchronized audio cues (1kg.8.6), campaign aggregate retention and cleanup (1kg.2.6), and the remaining contract checks under oarm. Consumer distribution and live audio capture have their own readiness and scope decisions.
